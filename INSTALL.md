# Установка ГККД — инструкция для Claude Code

Этот файл читает Claude Code (вкладка Code в приложении Claude или терминал), а не человек. Человек вставил в чат одну строку из README и ждёт, что ты всё сделаешь сам. Говори с ним простыми словами, на «ты», без технических подробностей, если он не спросил. Одно сообщение — одно действие с его стороны.

## Что должно получиться

Рабочая папка, в которой запущен Claude Code (дальше — «рабочая папка»):

    рабочая папка/
    ├── CLAUDE.md        ← памятка для следующих сессий (шаг 4)
    ├── gkkd/            ← система: агенты, методички, библиотека
    ├── repos/           ← методички и отдельный promt-seo-geo/
    └── projects/        ← проекты экспертов, создаёт Фиксик

## Шаг 0. Проверь рабочую папку

- Посмотри, где запущен Claude Code.
- Если это домашняя папка пользователя, рабочий стол или папка с чужими файлами — не ставь туда. Скажи человеку: «Давай поставим систему в отдельную папку. Создай пустую папку, например „ГККД“ в „Документах“, начни новую сессию во вкладке Code, нажми Select folder, выбери эту папку и снова отправь ту же строку». Дальше не продолжай.
- Найди корень ГККД: новая установка — `gkkd/`; прежние `promt-gkkd/` и `prompt-gkkd/` сохраняются без переименования. Если найдено несколько копий — остановись и выясни, какая рабочая; не выбирай молча. Все дальнейшие ссылки `gkkd/` подставляй фактическим именем.
- Уже установленную систему не клонируй и не обновляй без просьбы. Проверь недостающие зависимости по шагам 2–3; затем продолжи с места остановки. Для обновления — шаг 5.

## Шаг 1. Git

- Проверь `git --version`.
- Нет git:
  - macOS — запусти `xcode-select --install` и скажи человеку: «Появится окно установки инструментов разработчика — нажми „Установить“ и напиши мне, когда закончится».
  - Windows — `winget install --id Git.Git -e`; после установки попроси человека полностью закрыть и снова открыть приложение Claude, начать сессию во вкладке Code в той же папке и снова отправить строку.
  - Linux — `sudo apt install git` или пакетный менеджер дистрибутива; пароль вводит человек.

## Шаг 2. Скачай систему и методички

Скачай ГККД, методички и отдельный SEO/GEO в соседние папки. Движок не копируется внутрь ГККД. Ни рабочие проекты экспертов, ни личный сайт автора не клонируются.

Выполни следующий блок из рабочей папки через Bash. По умолчанию он только устанавливает отсутствующее; существующее проверяет и сохраняет. Функции действуют в этом же процессе. Значения удалённых адресов не выводи: они могут содержать доступы.

```bash
set -euo pipefail
mode=install
# Только по просьбе «обнови систему»: замени строку выше на mode=update.

stop() { printf '%s\n' "$*" >&2; return 1; }
check_repo() {
    local dir="$1" name="$2" top actual remote
    [ -d "$dir/.git" ] || [ -f "$dir/.git" ] || {
        stop "$dir: занято не рабочим Git-репозиторием; сохрани папку и выбери другое место."; return 1;
    }
    top=$(git -C "$dir" rev-parse --show-toplevel 2>/dev/null) || return 1
    actual=$(cd "$dir" && pwd -P)
    [ "$top" = "$actual" ] || { stop "$dir: вложенный путь вместо корня репозитория."; return 1; }
    remote=$(git -C "$dir" remote get-url origin 2>/dev/null) || {
        stop "$dir: нет origin; нужен адрес ожидаемого репозитория."; return 1;
    }
    case "$remote" in
        https://*) remote=${remote#https://}; remote=${remote##*@} ;;
        git@github.com:*) remote="github.com/${remote#git@github.com:}" ;;
        ssh://git@github.com/*) remote="github.com/${remote#ssh://git@github.com/}" ;;
        *) stop "$dir: origin не соответствует ожидаемому GitHub-репозиторию."; return 1 ;;
    esac
    remote=${remote%/}; remote=${remote%.git}
    [ "$remote" = "github.com/BermanRoman/$name" ] || {
        stop "$dir: другой репозиторий; папка сохранена, клонирование поверх запрещено."; return 1;
    }
}
check_update() {
    local dir="$1" upstream
    [ -z "$(git -C "$dir" status --porcelain --untracked-files=all)" ] || {
        stop "$dir: есть местные изменения. Сначала согласуй их сохранение в отдельной ветке/коммите; автоматически не прячь и не сбрасывай."; return 1;
    }
    git -C "$dir" symbolic-ref -q HEAD >/dev/null || {
        stop "$dir: не выбрана ветка; выбери рабочую ветку после проверки."; return 1;
    }
    upstream=$(git -C "$dir" rev-parse --symbolic-full-name '@{upstream}' 2>/dev/null) || {
        stop "$dir: нет отслеживаемой ветки; сначала согласуй нужную ветку origin."; return 1;
    }
    case "$upstream" in refs/remotes/origin/*) ;; *)
        stop "$dir: upstream не в origin; сначала согласуй ветку обновления."; return 1 ;;
    esac
}
ensure_repo() {
    local dir="$1" name="$2"
    if [ -e "$dir" ] || [ -L "$dir" ]; then
        check_repo "$dir" "$name"
    else
        git clone "https://github.com/BermanRoman/$name.git" "$dir" >/dev/null 2>&1 || {
            stop "$dir: скачивание не завершилось. Проверь сеть и состояние папки; ничего не удаляй автоматически."; return 1;
        }
        check_repo "$dir" "$name"
    fi
}
update_repo() {
    local dir="$1"
    check_update "$dir"
    git -C "$dir" fetch origin >/dev/null 2>&1 || {
        stop "$dir: не удалось получить обновление; проверь сеть и доступ, значения доступов не выводи."; return 1;
    }
    git -C "$dir" merge-base --is-ancestor HEAD '@{upstream}' || {
        stop "$dir: есть местные коммиты или ветки разошлись. Нужен отдельный разбор; merge/rebase/reset автоматически не выполняй."; return 1;
    }
    git -C "$dir" merge --no-overwrite-ignore --ff-only '@{upstream}' >/dev/null 2>&1 || {
        stop "$dir: обновление остановлено без принудительного сброса; проверь состояние ветки и конфликт с локальными, в том числе игнорируемыми, файлами."; return 1;
    }
    printf '%s\n' "$dir: проверено и обновлено без слияния веток."
}

system_dir=gkkd
found=0
for candidate in gkkd promt-gkkd prompt-gkkd; do
    if [ -e "$candidate" ] || [ -L "$candidate" ]; then
        found=$((found + 1)); system_dir="$candidate"
    fi
done
[ "$found" -le 1 ] || { stop 'Найдено несколько папок ГККД: сначала выбери рабочую.'; exit 1; }
case "$mode" in install|update) ;; *) stop 'Неизвестный режим.'; exit 1 ;; esac
libraries=(prompt-audience-research prompt-spin-questions promt-source-life promt-hvco prompt-clip-landing promt-copywriting promt-seo-geo)
# Сначала проверка всех имеющихся папок; до её завершения ничего не скачивай.
for name in promt-gkkd "${libraries[@]}"; do
    dir="repos/$name"; [ "$name" != promt-gkkd ] || dir="$system_dir"
    if [ -e "$dir" ] || [ -L "$dir" ]; then
        check_repo "$dir" "$name"
        if [ "$mode" = update ]; then check_update "$dir"; fi
    fi
done
mkdir -p repos
ensure_repo "$system_dir" promt-gkkd
for name in "${libraries[@]}"; do ensure_repo "repos/$name" "$name"; done
if [ "$mode" = update ]; then
    update_repo "$system_dir"
    for name in "${libraries[@]}"; do update_repo "repos/$name"; done
fi
```

Если произошла ошибка, не продолжай запуск. Уже завершённые установки и обновления сохраняй; сообщи, на какой папке остановился процесс. После устранения причины блок можно повторить: существующие папки не перезаписываются. При сетевом сбое допускается одна повторная попытка после проверки состояния; незавершённую папку не удаляй и не обходи проверку origin.

Скачивание SEO/GEO здесь — установка исходников. Подготовку Node.js, зависимостей, workspace и проверку сборки выполняет отдельная SEO/GEO-сессия по её актуальному README, когда нужен сайт. ГККД не запускает SEO onboarding при установке воронки.

## Шаг 4. Памятка для следующих сессий

Создай в рабочей папке `CLAUDE.md`, если его нет, с текстом ниже. Вместо `gkkd/` подставь фактическое имя папки. Существующий файл не заменяй: согласованно дополни только отсутствующие указатели, сохрани прежние правила.

    # Система ГККД

    - Корень ГККД — `gkkd/`. Пути agents/, knowledge/, library/, core/ внутри системы считаются от её корня.
    - Методички — `repos/` рядом с ГККД; проекты экспертов — `projects/`.
    - «Начинаем», «продолжаем», вопросы про воронку/продукт/бота — работай по `gkkd/agents/00-fiksik.md`, найди проект и место остановки.
    - «Обнови систему» — раздел «Обновление» в `gkkd/INSTALL.md`.
    - SEO/GEO — отдельная система в `repos/promt-seo-geo/`, не агент ГККД. Для сайта сначала `gkkd/knowledge/seo-handoff.md` и пакет конкретного эксперта.
    - Родительская сессия ГККД не исполняет мастер-промт SEO/GEO. Для SEO открывается отдельная сессия в корне SEO-репозитория с его собственными инструкциями и явным абсолютным путём к проекту эксперта.

Для Codex аналогичный короткий указатель допускается в `AGENTS.md`; существующие инструкции сохраняй. Не склеивай `CLAUDE.md` двух систем и не копируй мастер-промт одной системы в другую. Новая сессия не отменяет родительских правил среды: проверь, что они допускают работу SEO, и зафиксируй границу ролей. При конфликте останови передачу и разбери применимые инструкции, а не обходи их.

## Шаг 5. Обновление (по просьбе человека)

Повтори блок шага 2 в режиме `mode=update` из общей рабочей папки. Он проверяет origin, чистоту, ветку и upstream; затем получает изменения и допускает только fast-forward. Грязная папка, местные коммиты, расхождение веток или отсутствие upstream — остановка с причиной, без stash, reset, удаления и автоматического rebase. Служебные неотслеживаемые файлы среды тоже считаются местными изменениями; не удаляй их ради обновления.

Проекты в `projects/` и рабочие данные SEO не обновляй этим блоком. Зависимости движка после его обновления проверяет SEO/GEO по собственному README. В итоге перечисли успешно обновлённые папки и остановки; не называй частичное обновление полным.

Команды выполняй сам; шаги в браузере Яндекса делает человек, ты подсказываешь по одному. Секреты (токен, ключ) человек в чат не присылает — следуй разделу о секретах в инструкции.
- «Нет» или «потом» — идём дальше.

## Шаг 7. Запуск

1. Скажи человеку коротко: система стоит, где лежит, что дальше начнёт Фиксик. Подскажи один раз: «Если я спрашиваю разрешение на каждый файл — выбери режим Accept edits рядом с кнопкой отправки (в терминале — Shift+Tab)».
2. Прочитай `gkkd/agents/00-fiksik.md` и работай по нему. Полный путь к папке методичек для заданий агентам — абсолютный путь к `repos/` в рабочей папке.

## Чего не делать

- Не меняй файлы в `gkkd/` и `repos/` — это система; обычная работа эксперта идёт в его проекте. Местные правки сохраняй, обновление при них останавливай.
- Не ставь ничего глобально, кроме git и того, что требует инструкция Wordstat.
- Не проси человека открывать файлы и копировать пути — всё делаешь сам.
