# Установка и обновление локальной ГККД

Инструкция предназначена агенту с доступом к локальным файлам и Git; выбранную модель, приложение и подключения пользователя сохраняй.

Говори с человеком просто, выполняй обычные рабочие действия сам и запрашивай только отсутствующие существенные решения.

## 1. Найти рабочее место

Используй указанную пользователем папку; если она общая, создай внутри отдельный каталог системы, сохранив соседние проекты.

Не устанавливай в домашний или системный корень по умолчанию, не требуй пустой папки, если пользователь уже назначил подходящую рабочую.

Найди существующий `gkkd/`, `promt-gkkd/` или явно указанный корень; прежнее имя не меняй, при нескольких копиях используй зафиксированный указатель, а существенную неоднозначность уточни.

По умолчанию структура такая:

```text
workspace/
  gkkd/       # библиотека
  repos/      # зависимости или указатель на существующий корень клонов
  projects/   # приватные проекты экспертов
  AGENTS.md   # короткий указатель для соответствующей среды
```

Если среда использует `CLAUDE.md`, указатель размещается там; существующие инструкции дополняются, не заменяются и не склеиваются с мастер-промптом SEO/GEO.

Проверь `git --version` и `python3 --version`; Python 3 нужен для локальных проверок, а не для вызова модели или сетевой отправки.

Отсутствующий инструмент установи поддерживаемым локальным способом в рамках поручения; запрос системного пароля/подтверждения передай человеку, секрет не принимай в чат.

## 2. Проверить библиотеку и зависимости

У существующего клона проверь фактический корень, origin, HEAD, статус дерева и ветку; URL с учётными данными не выводи.

Допустимые адреса ожидаемых публичных репозиториев — HTTPS или SSH `BermanRoman/<имя>` на GitHub; неожиданное назначение не исправляй автоматически.

Чистая новая установка библиотеки: клонируй `https://github.com/BermanRoman/promt-gkkd` только в отсутствующий каталог, затем следуй инструкциям полученной версии.

Чужой каталог, изменённые файлы, незавершённая установка или расхождение истории сохраняются; не применяй reset, stash, clean, удаление либо автоматический rebase ради установки.

Проверенные версии четырёх модернизированных компонентов находятся в `dependencies.json`, маршруты — в `integrations/components.md`.

Сначала ищи уже существующие подходящие клоны в назначенной рабочей области; общий абсолютный корень передай как `--repos-root`, не скачивай вторую копию без необходимости.

Для нового отсутствующего клона используй `git clone --no-checkout` ожидаемого публичного репозитория, затем `git checkout --detach <commit-из-manifest>` внутри только этого нового клона.

Если закреплённый коммит недоступен, получи его из ожидаемого origin; не заменяй веткой main или похожим SHA по догадке.

Существующий клон с другой ревизией или локальными правками не переключай: сохрани его, создай отдельный корень совместимых зависимостей при необходимости и запиши выбранный путь для проекта.

В одном назначенном корне сохраняются ожидаемые имена каталогов; не подменяй их symlink на случайные рабочие версии.

Проверка из корня ГККД:

```sh
python3 scripts/check_structure.py
python3 scripts/check_dependencies.py --repos-root /absolute/path/to/repos
```

При адресной установке допустим `--route audience`, `--route hvco`, `--route clip` или `--route copywriting`; последний проверяет общие методички, а HVCO/clip также проверяют копирайтинг.

Успех выбранного маршрута не означает установленность всех остальных; отсутствие неиспользуемого компонента не блокирует независимую диагностику.

Проверка сопоставляет реальный HEAD и байты каждого закреплённого файла с Git-объектом, включая изменения, скрытые индексными флагами; она ничего не обновляет.

Для незакреплённых дополнительных компонентов `promt-source-life` (диагностика: `spin-core.md`, `behavior-methodology.md`) и `prompt-spin-questions` (бот: `spin-questions.md`) применяй тот же контроль origin/чужих изменений, записывай фактический commit и проверяй нужные файлы перед ролью.

Они не включены в проверку совместимости четырёх модернизированных компонентов; отсутствие/смена их версии требует проверки соответствующего маршрута, а не заявления «всё проверено».

Отдельный `promt-seo-geo` нужен только при передаче сайта по `knowledge/seo-handoff.md`; его установку, зависимости и сборку выполняют по собственным инструкциям в отдельной сессии, без автоматического запуска при установке ГККД.

Система ГККД не устанавливает глобальные npm-пакеты и не меняет конфигурацию моделей для экономии.

## 3. Короткий указатель и запуск

В установочной памятке сохрани абсолютные корни ГККД, зависимостей и проектов, текущий проект и источник закреплённых версий.

Минимальный указатель:

```text
ГККД: <абсолютный корень системы>.
Зависимости: <абсолютный корень клонов>, версии по dependencies.json.
Проекты экспертов: <абсолютный приватный каталог>.
«Начинаем/продолжаем» — agents/00-fiksik.md, сначала существующий паспорт и место остановки.
«Обнови систему» — INSTALL.md; проекты и личные данные сохраняются.
SEO/GEO — отдельная система и сессия по knowledge/seo-handoff.md, не роль Фиксика.
```

Не переписывай весь промпт в памятку и не записывай секреты.

Прочитай `agents/00-fiksik.md`, его стартовую карту чтения и начни/возобнови выбранный проект; не проводи диагностику заново из-за переустановки указателя.

Для составной задачи Фиксик подключает нужные профили из `teams/` по `core/teams.md`; устанавливать или запускать все шесть координаторов заранее не требуется.

Возможность вложенного вызова проверяется в текущей среде; при её отсутствии Фиксик запускает исполнителей по заданиям координатора, сохраняя владельцев и независимость проверок.

## 4. Обновление по поручению

Сначала проверь origin, чистоту, текущую ветку/upstream и отсутствие местных коммитов; библиотеку обновляй только fast-forward ожидаемой ветки.

Грязный клон, detached HEAD библиотеки, отсутствие upstream или расхождение веток — зафиксированный пробел обновления, без принудительного переключения.

После обновления прочитай новые decisions.md и manifest, сравни изменившиеся закреплённые зависимости и используемые контракты.

Зависимости не обновляются слепым pull всех main: нужные версии берутся из нового manifest, существующие рабочие клоны сохраняются по §2.

Проекты экспертов, исходные файлы и рабочие данные SEO не обновляются вместе с библиотекой; в проекте отмечаются лишь зависимые результаты, затронутые изменением правил/данных.

После изменения повтори нужную структурную/маршрутную проверку и сообщи точный охват; частичный результат не объявляй полной установкой или обновлением.

При сетевом сбое проверь состояние и причину, допускается один обоснованный повтор; незавершённый каталог не удаляй автоматически.

## 5. Подключения и границы результата

Сначала используй уже настроенные и разрешённые средства исследования; не запускай повторную настройку Wordstat, если он доступен.

Новая настройка Wordstat предлагается один раз при необходимости по `knowledge/wordstat-setup.md`, отказ/отсрочка сохраняется; расходы и доступы не подразумеваются установкой ГККД.

Сайты и боты собираются по своим адаптерам и действующему поручению; логин, платёжные данные, оплата и публикация остаются в границах полномочий из core/handoff.md и decisions.md.

Без нужного инструмента/доступа готова инструкция или материал, а не якобы собранная и проверенная воронка.
