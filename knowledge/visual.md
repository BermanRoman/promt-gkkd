# Методичка Арт-директора

Теория для агента `agents/07-art.md`. Эксперту её термины не показываются.

Опоры: `decisions.md` (2.1, 3.7, 3.9, 16, 18, 21 — Р-3); `knowledge/methodology.md` (M§3.2–3.4, M§4.7, M§8.6, M§12); `analysis/rbh/landings.md` (1, 2.3); `library/modules.md` (В-1, В-2, П-1…П-7, Ц-14); `knowledge/texts.md` (§1, §3, §5, §8); `prompt-clip-landing` (шкала состояний, структура 5 страниц); WCAG 2.2; справки мессенджеров — с датой проверки в §6.
**Рамки визуала:** витрина (хаб «обо мне», оформление канала или группы, стартовые посты), страницы, на которые ведёт бот («Подробно о продукте», анкета, оплата, «ссылка закрылась»), посадочная — только для внешнего трафика и продукта выше 2 медиан (П-1; M§3.3), материалы бота и практикума. Рекламные креативы, обложки роликов и всё, что относится к трафику, — вне рамок системы (M§0.3). Сервис сборки не называется: ТЗ пишется для любого конструктора страниц, ИИ-дизайнера или живого дизайнера (M§12).

## 1. Принципы

1. **Визуал не громче текста.** Урок РБХ: спокойный прогрев и громкий продажник ломают доверие (`analysis/rbh/landings.md`, 2.3). «Подробно о продукте», страница оплаты, «ссылка закрылась» и картинки к сообщениям окна — в тех же цветах, шрифтах, отступах и характере фото, что витрина и серия. Страница продукта отличается только структурой: списки, шаги, таблица «что входит». Громкость не растёт.
2. **Картинка не обещает больше текста.** Визуал не показывает результат, которого нет в тексте и оферте. Цифры, отзывы, логотипы, дипломы, «нас читают» — только если они есть в `06-texts/` дословно.
3. **Текст на визуале — дословно из `06-texts/`.** Нужной строки нет — запрос агенту «Тексты» через Фиксика. Пометки вида `[нужен кейс]` идут в макет как есть, выделенной плашкой: это пробел, который заполнит эксперт.
4. **Mobile-first.** Макет сначала под экран телефона шириной 360–390 px, потом адаптация под компьютер `[ДОПУЩЕНИЕ: диапазон ширин — ориентир]`.
5. **Один экран — одна главная кнопка, один акцентный цвет.** Акцент — только кнопки и одно ключевое выделение на экране. Вторая кнопка — только если она есть в тексте (оплата сразу и частями): контурная, рамка цветом акцента, без заливки.
6. **Живое лицо и процесс сильнее глянца.** Для «ореха» доверие дают реальное лицо эксперта, его рабочий процесс, реквизиты и неидеальные живые фото, а не студийный блеск и роскошь (M§3.2, M§4.7).

**Запрещено на любом визуале:** таймеры и счётчики (реальный срок пишется текстом из `06-texts/`); «осталось N мест»; зачёркнутые цены, кроме реальной скидки за путь (О-1) с её строкой из текста; бейджи «хит», «−90 %», «только сегодня»; красный цвет для цены и срока; капслок целых фраз; неон, мигание, вспышки; стрелки и указующие пальцы; шок-образы, слёзы, драма.

## 2. Задачи экранов

**Откуда задача.** В страницах агент «Тексты» ставит строку «Экран N. Задача: …» (`knowledge/texts.md`, §1, «Страницы»). Её и берёшь. Строки нет — задача по таблицам ниже, с пометкой `[ДОПУЩЕНИЕ: задача экрана]`. Страница магнита (П-3): секция текста = экран, задача — из строки «Экран N. Секция: … Задача: …»; название секции на страницу не ставится.

### 2.1. Клип-лендинг (П-1) — по шкале состояний

Делается, только если строка есть в `05-funnel.md`, п. 7: клип-лендинг нужен для внешнего трафика и для продукта выше 2 медиан (M§3.3; Р-3). По умолчанию человек идёт из ролика прямо в бота.

| Страница | Состояния | Задача визуала | Чего нет |
|---|---|---|---|
| 1 | Боль + следствие боли | Узнавание: бытовая деталь из текста страницы — предмет, обстановка. Спокойный свет | продукта, логотипа, цены, эксперта |
| 2 | Следствие боли + страх ухудшения | «Дело не во мне»: деталь из текста о других людях или о системе. Та же палитра, без мрачных фильтров | решения, результата |
| 3 | Потребность в изменениях + желание улучшений | Первая попытка: та же обстановка, что на странице 1, с переменой, которая описана в тексте | механизма, цены |
| 4 | Вера в улучшения | Механизм: шаги или схема простыми блоками, если они есть в тексте; «кому подходит» — списком | цены и условий |
| 5 | Выгода + супервыгода + помощь | «Обычный день» из текста; первый шаг — заметная кнопка без давления | таймера, цены, если её нет в тексте |

**Рассказчик** — один на все 5 страниц, в одном стиле.
- Реальный клиент с согласием — его фото, если он его дал письменно (ст. 152.1 ГК РФ).
- Собирательный (по умолчанию, `knowledge/texts.md`, §3) — нарисованная иллюстрация в стиле, который не путается с фото, или фото предметов и обстановки без лица. Без имени, возраста и города под картинкой, без рамки «отзыв», звёзд и кавычек-отзыва. Строка «Героиня собирательная: …» из текста стоит на каждой странице читаемым размером, не мельче основного текста на один шаг.

### 2.2. «Подробно о продукте» (П-4) — по блокам каркаса

Касание по желанию: на страницу ведёт ссылка из питча или из ответа на частый вопрос в боте (M§6.5). Порядок блоков = порядок экранов (`knowledge/audience.md`, §7).

| Блоки | Визуальный приём |

| 1. СТП | Первый экран: заголовок, подзаголовок, кнопка, место под фото эксперта |
| 2. Идентификация | Два списка «кому подходит» и «кому не подходит» одного веса; 3 обещания — три карточки одного размера |
| 3. Точка А | Текстовый блок, можно фото-фон обстановки из жизни клиента мечты без людей |
| 4. Пошаговый план | Нумерованные шаги, у каждого — результат шага |
| 5. История Золушки | Фото эксперта; кейсы — только реальные, с согласия (В-32, п. 4), без «до/после» тела |
| 6–8. Вера в себя, сервис, самостоятельное решение | Текст и простые линейные значки; без мотивационных картинок и «красных крестов» |
| 9–13. Предложение, ценность, отстройка, кому не подходит, гарантии | Таблица стека «что получите — какую проблему снимает — чем подтверждена ценность» из текста; цена — шрифтом заголовков, без зачёркиваний, кроме реальной скидки О-1 по §1; рассрочка рядом с ценой тем же весом; гарантия — три части дословно, обычным размером, не сноской |
| 14. Ответы на вопросы | Раскрывающийся список или вопрос-ответ |
| 15. Итог | Кнопка того же вида, что на первом экране |

### 2.3. Остальные страницы

- **П-2, хаб «обо мне»:** см. §2.4.
- **П-3, страница магнита:** длинное чтение — узкая колонка, подзаголовки, схема — вёрсткой по тексту, если она есть в тексте. Магнит может быть сообщением бота — тогда визуал по §2.5.
- **П-5, после регистрации:** шаги нумерованным списком; **срок доступа и дата окончания — на первом экране**, не мельче основного текста, выделены рамкой или цветом акцента. В РБХ дата не была закреплена в момент наибольшего внимания (`analysis/rbh/landings.md`, 1). Без таймера.
- **П-6, анкета:** один вопрос — одно поле; чекбокс согласия без галочки, ссылка на документ рядом; вилка цены видна до кнопки.
- **П-7, оплата:** итог из оферты, цена, условия возврата; галочка допродажи не стоит. Оплата сразу и частями — две кнопки: основная залитая, вторая контурная. Личная ссылка и её срок (`{ссылка_оплаты}`) на статичной странице не работают — флаг в отчёте (промт, Шаг 3).
- **Плашка cookies** — на каждой странице, которая ставит счётчик посещаемости или cookies: внизу экрана, текст дословно из строки «Cookies:» текста страницы, не перекрывает кнопку экрана. Строки «Cookies:» нет — плашки нет.
- **«Ссылка закрылась»:** что произошло и что дальше, спокойно.

### 2.4. Витрина (В-1)

Задача витрины — человек после ролика проверяет автора и находит, чем убедиться (M§3.2). Визуал отвечает на «это живой человек и он не мошенник».
- **Аватар канала или группы** — живое лицо эксперта крупно (портрет Ф-n), без логотипа вместо лица. Эксперт не показывает лицо — фото процесса или рабочего места (особые случаи промта).
- **Обложка канала или сообщества** — эксперт за работой или место работы; текст на обложке — только строка из текста витрины (кто я одной фразой).
- **Закреп** — пост с картинкой: фото эксперта или процесса; на картинке без текста или строка из закрепа дословно; кнопка или ссылка в бота — та, что в тексте.
- **Хаб «обо мне» (П-2)** — страница: первый экран — лицо эксперта и кто он одной фразой; дальше процесс работы (фото Ф-n), «кому не подхожу» обычным текстом, цена «от» тем же весом, что остальной текст, реальные отзывы с согласием (скриншоты с закрытыми данными), реквизиты не мельче основного текста на один шаг. Без логотипов СМИ, «нас читают», дипломов-коллажей.
- **Стартовые посты** — обложки постов и карусели по строкам «Слайд N.» и «В кадре:» текста. Один шаблон на все посты: та же палитра и шрифты, что страницы.
- **Чего нет:** роскоши, шок-цифр дохода, «до и после», стоковых лиц, бейджей «эксперт №1».

### 2.5. Материалы бота и практикума

- **Картинки к сообщениям бота** — только там, где строка есть в п. 7 и текст сообщения её называет («В кадре:» или схема в тексте): первое сообщение (лицо эксперта, тот же кадр, что на витрине), обложка магнита, схема или таблица из текста магнита. Одна картинка — одно сообщение. Текст на картинке — только строка из текста дословно.
- **Магнит файлом** (PDF или карточки) — если п. 7 так называет формат: страницы по экранам текста, узкая колонка, схемы вёрсткой; обложка — название магнита дословно и фото эксперта или Г-фон.
- **Практикум** (Ц-14) — карточка каждого дня: номер дня, задание и маленькая победа дословно из текста дня, место для отметки «сделано», если она есть в тексте. Все дни — один шаблон. Сертификат или итоговая карточка — только если строка есть в п. 7, по факту выполнения, без «гарантированного результата» (M§8.6).
- **Схемы метода** (тарелка, упражнение, план) — вёрстка по тексту эксперта или его живое фото, не генератор (§7). Схемы нет в тексте — нет и картинки.
- **Формат** — под экран телефона в мессенджере: вертикаль 4 : 5 или квадрат 1 : 1 `[ДОПУЩЕНИЕ: ориентир]`; размеры — §6.

## 3. Блок стиля

1. **Настроение** — 3 слова из входов: ниша, клиент мечты и big idea (раздел 4 паспорта), голос эксперта (1.5). Плюс 3 слова «чего избегать».
2. **Палитра** — 5 ролей с HEX: фон; основной текст; акцент (кнопки); вторичный фон (карточки); приглушённый текст (подписи).
3. **Контраст** (WCAG 2.2, критерии 1.4.3 и 1.4.11):
   - основной текст на фоне — от 4,5 : 1;
   - крупный текст (от 24 px или от 18,66 px жирным) — от 3 : 1;
   - текст кнопки на акценте — от 4,5 : 1 `[ДОПУЩЕНИЕ: строже минимума, кнопка — главный элемент]`;
   - граница кнопки и полей формы относительно фона — от 3 : 1.
   Расчёт: каждый канал c = значение / 255; если c ≤ 0,04045, то c / 12,92, иначе ((c + 0,055) / 1,055) ^ 2,4. Яркость L = 0,2126 R + 0,7152 G + 0,0722 B. Контраст = (L светлого + 0,05) / (L тёмного + 0,05). Цифра пишется рядом с каждой парой. Посчитать нечем — `[проверить контраст: пара]`.
4. **Шрифты** — 2 из Google Fonts: для заголовков и для текста (или одна гарнитура в двух начертаниях). Проверка: на fonts.google.com фильтр языка Cyrillic, затем в превью набрать «Ёё Йй Ъъ « » — № ₽». Знака нет — другой шрифт. Сайт не открывается — второй способ: скачать файл шрифта из github.com/google/fonts и проверить программой, что коды всех знаков есть в таблице символов (cmap); проверено так — пометка не нужна. Нет ни того, ни другого — шрифт из примеров ниже с пометкой `[ДОПУЩЕНИЕ: знак ₽ не проверен]`. Примеры с кириллицей, проверка всё равно обязательна: Golos Text, Inter, Manrope, Montserrat, PT Sans, PT Serif, Lora, Rubik, Nunito, IBM Plex Sans.
5. **Размеры на телефоне** `[ДОПУЩЕНИЕ: ориентир]`: основной текст 16–18 px, межстрочный 1,5; заголовок экрана 28–36 px; подзаголовок 22–26 px; кнопка высотой от 48 px (минимум по WCAG 2.2, критерий 2.5.8, — 24 × 24 px). Картинки постов и сообщений (слайд и обложка шириной 1080 px) — размеры долями кадра, а не в px блока стиля: заголовок ≈ 1/12–1/15 ширины, основной текст ≈ 1/20–1/25, поля — 8 % с каждой стороны `[ДОПУЩЕНИЕ: ориентир]`.
6. **Отступы и сетка** `[ДОПУЩЕНИЕ: ориентир]`: шаг 8 px; поля по бокам 16–20 px; между блоками 48–64 px; внутри блока 16–24 px; одна колонка на телефоне, строка на компьютере — до 70 знаков.
7. **Характер фото:** живые фото эксперта и места работы, дневной свет, естественные цвета, без бьюти-ретуши и коррекции фигуры. Фоны и иллюстрации из генератора — в палитре проекта.
8. **Чужие бренды:** не берутся логотипы, фирменные сочетания цветов и шрифтов узнаваемых брендов и конкурентов, нет «как у [бренд]». Визуальная система Романа Бермана («Лавка Бермана»: тёмный editorial-стиль, Unbounded + Onest, жёлтый акцент) и её близкие повторы клиентам не выдаются.

## 4. Живое фото: заглушки и список съёмки

**Подпись заглушки** — 5 полей: что в кадре · кадр (крупно, по пояс, в рост; вертикаль 4 : 5, 9 : 16 или горизонталь 16 : 9 — по месту в макете) · фон · свет · одежда и детали.

**Как снимать на телефон** `[ДОПУЩЕНИЕ: практические правила, не из источника]`:
- основная камера, не фронтальная; протереть объектив;
- дневной свет из окна сбоку или спереди, не за спиной;
- камера на уровне глаз, телефон на опоре или в руках помощника;
- фон без бытового хаоса; на работе — рабочее место;
- без фильтров, бьюти-режима и коррекции фигуры;
- 3–5 дублей каждого кадра; файлы в исходном размере, не через мессенджер со сжатием.

**Типовой набор:** портрет для аватара и первого экрана (лицо крупно, для круглой обрезки — с запасом по краям); за работой — для обложки канала и хаба; место работы; детали (инструмент, рабочий стол, тетрадь с планом без чужих данных).

**Другие люди в кадре** — клиенты, ученики, посетители зала — только с их письменного согласия (ст. 152.1 ГК РФ). Скриншоты переписки — с закрытыми именами, аватарами и телефонами.

## 5. Ниша здоровья и закон

### 5.1. Правило системы

Действует в нише здоровья всегда: на витрине, на страницах, в материалах бота и практикума, даже с реальными фото и согласием `[ДОПУЩЕНИЕ: перечень составлен системой]`:
- нет «до/после» тела и внешности;
- нет весов с цифрой, сантиметровой ленты на теле, крупных планов «проблемных зон», тела как результата;
- текст экрана, обложки или слайда называет вес или размер эксперта или клиента «тогда» («набрала 18 кг») — на этом месте нет фото фигуры этого человека: только руки, предметы, обстановка. Цифра «тогда» рядом с телом «сейчас» — «до и после» без второй фотографии;
- портрет эксперта — по пояс или крупнее, в обычной одежде, без акцента на фигуру: не облегающий топ, не поза «показать форму» `[ДОПУЩЕНИЕ]`;
- нет таблеток, шприцев, капельниц, медицинских процедур; белый халат — только если эксперт врач и это есть в тексте.

Причина: картинка обещает результат для тела, а медицинские обещания запрещены (`decisions.md`, 3.9; `knowledge/texts.md`, §3). Перемены — действия, распорядок, «обычный день».

### 5.2. Закон

- **Изображение человека** — только с его письменного согласия (ст. 152.1 ГК РФ): клиенты, ученики, посетители зала (§4).
- **38-ФЗ, ст. 24** — если услуга эксперта медицинская (методы профилактики, диагностики, лечения, реабилитации) и материал может считаться рекламой: нельзя ссылаться на конкретные случаи улучшения здоровья и благодарности людей (ч. 1, п. 2–3; ч. 6); нужно предупреждение о противопоказаниях, в изображении — не меньше 5 % площади (ч. 7). Источник: текст закона, rulaws.ru, проверено 2026-10-05. Относится ли это к конкретному эксперту и его витрине — решает юрист ⚖.
- Реклама и её правила — вне рамок системы (M§0.3).

## 7. Промты для генератора изображений

Только фото-фоны, предметы, обстановка, места и иллюстрации. Без фотореалистичных людей, без лиц эксперта и «клиентов», без текста.

Не генерируется то, что выглядит как метод эксперта: схема тарелки, упражнение, план, «правильная» порция. Это живое фото эксперта или схема вёрсткой по тексту. Схемы нет в тексте — нет и картинки (промт, Шаг 0).

**Структура промта** (без привязки к сервису):
1. **Назначение:** ID картинки и место в макете.
2. **Объект:** что в кадре, конкретно, из детали текста экрана.
3. **Композиция:** план, ракурс, где пустое поле под текст.
4. **Свет:** время суток, источник, мягкость.
5. **Стиль:** фото или иллюстрация; палитра проекта словами («тёплый бежевый, приглушённый зелёный»).
6. **Формат:** соотношение сторон по месту в макете.
7. **Исключить:** люди с лицами, руки крупно, текст, буквы, цифры, логотипы, водяные знаки; в нише здоровья — всё из 5.1.

**Адаптация** — под генератор, который выбрал эксперт, без названий в файлах проекта (M§12): промт обычными предложениями; формат и исключения — отдельным полем, если оно есть, иначе фразой в конце («без людей, без текста и букв»). Генератор понимает только английский — эксперт переводит промт целиком, не сокращая пункт «Исключить» `[ДОПУЩЕНИЕ]`.

## 8. Как собрать страницу в любом сервисе и шаблон правок

**Кто собирает:** конструктор страниц, ИИ-дизайнер или живой дизайнер — по выбору эксперта (M§12.3). ТЗ одинаковое для всех: самодостаточное, с блоком стиля внутри, без системных пометок.

**Что должен уметь сервис** (проверить до выбора): одна колонка на телефоне; свои цвета по HEX; шрифты из блока стиля или их загрузка файлом; кнопка со ссылкой на бот или оплату; замена картинки без смены размера и места; подвал со ссылками на документы. Чего сервис не умеет — ближайшая замена: шрифт — ближайший с кириллицей и знаком ₽ из §3, п. 4; цвет — тот же HEX вручную. Личная ссылка и её срок на статичной странице не работают — кнопка ведёт в бот (`knowledge/texts.md`, §1).

**Порядок для эксперта** (раздел «Как этим пользоваться» в файле стиля), 5 шагов:
1. Выбрать, где собирать: конструктор страниц, ИИ-дизайнер или дизайнер.
2. Скопировать ТЗ страницы от «НАЧАЛО ТЗ» до «КОНЕЦ ТЗ» и передать целиком: вставить одним сообщением ИИ-дизайнеру, отправить дизайнеру или собирать по нему экран за экраном в конструкторе. Блок стиля уже внутри ТЗ.
3. Снять фото по списку съёмки; картинки Г сделать в генераторе по промтам.
4. Поставить фото и картинки на место заглушек: «Поставь это фото вместо заглушки Ф-[n]. Размер и место не меняй» (для картинки — «вместо Г-[n]»).
5. Сверить макет с ТЗ и поправить фразами ниже.

**Шаблон правок** — 4 фразы (`decisions.md`, 3.7), номер экрана подставляет агент. Подходят и для ИИ-дизайнера, и для дизайнера, и как список проверки при сборке своими руками:
1. «Экран [N]: текст отличается от ТЗ — верни слово в слово из ТЗ».
2. «Экран [N]: [заголовок / кнопка] плохо видно — сделай крупнее, кнопку — цветом акцента и во всю ширину. Текст не меняй».
3. «Экран [N]: тесно или картинка закрывает текст — добавь воздуха по отступам из блока стиля, картинку поставь под заголовком».
4. «Экран [N]: слишком ярко или не в стиле — верни цвета и шрифты из блока стиля».
