# Проверка командной организации — 05.11.2026

## Что изменилось

Главный Фиксик управляет нужными направлениями, координатор собирает работу специалистов внутри своего пакета.

Шесть направлений охватывают стратегию, вход и прогрев, продажи, вебинары и запуски, сопровождение и повторные покупки, аналитику и рост.

Двенадцать предметных ролей, пять человеческих развилок, полные методики, три общих круга Клиента мечты и отдельный Контролёр сохранены.

Организационный канон — [core/teams.md](../core/teams.md), предметные контракты — [core/handoff.md](../core/handoff.md).

Для малой прямой задачи координатор и отдельная доска не обязательны.

Координатор получает контракты и нужные критерии, исполнитель — полный промпт своей роли и обязательные методики; все шесть команд не читают весь корпус заранее.

## Найденные и исправленные проблемы

| Проблема | Исправление |
|---|---|
| Разные команды могли запрашивать повторную генерацию всей основы и полного списка | Выданные ID ограничивают локальное производство; общий этап принимается только по полному объединению результатов |
| Разные разделы одного паспорта предполагали параллельную запись | Право записи выдаётся последовательно на весь физический файл; владельцы разделов сохранены |
| Раздельные страницы могли получать несовместимый стиль и одинаковые ID разных кадров | Общая подготовка стиля и реестра фото/генераций одним владельцем до зависимых пакетов |
| Продажи, запуски и сопровождение используют общие бот-файлы | Один владелец последовательно собирает общий комплект, проверяет переходы и очереди |
| Создание доски оставалось безусловным даже при простой правке | Доска обязательна для составной задачи; малый вызов учитывается в паспорте и пакете |
| SHA всей доски блокировал запуск после служебного назначения исполнителя | Полномочия проверяются по актуальным полям доски; содержательные входы сохраняют строгую проверку SHA |

Отдельное архитектурное ревью повторно проверило исправления и не оставило блокирующих замечаний.

## Фактический организационный прогон

В приватной синтетической фикстуре участвовали отдельные координатор и исполнитель; вложенный запуск был заменён явной передачей через ведущего.

Координатор получил утверждённую цену 3500 ₽ и два текста со старой ценой 3000 ₽.

Предложение двух продающих напоминаний всем, включая оплативших, было отклонено по общей карте без изменения канонов и без блокировки независимой правки цены.

Первый пакет остановился до записи из-за изменения SHA доски после назначения исполнителя; эта фактическая остановка привела к исправлению правила изменяемой доски.

Второй пакет прошёл: отдельный исполнитель изменил только два назначенных текста, сохранив остальные байты и канонические входы.

Для проверки приёмки ведущий намеренно вернул старую цену в один выходной файл уже после успешного отчёта исполнителя.

Координатор перечитал фактические файлы, отклонил комплект и выдал адресную F-01 только на повреждённый материал; исправный материал остался только для чтения.

Это контролируемая подмена тестового результата, а не ошибка первоначальной операции исполнителя.

Исполнитель выполнил адресное исправление только второго файла; координатор повторно сверил оба выхода и неизменность канонов, закрыл F-01 и зафиксировал освобождение записи.

Итоговые SHA двух материалов совпали с ожидаемой точной заменой; обратная замена восстановила исходные SHA, остальные байты сохранились.

## Проверки и ограничения

Структурная проверка расширена на шесть профилей координаторов, их метаданные и локальные ссылки.

17 регрессионных тестов инструментов прошли; четыре закреплённые зависимости совпали с ожидаемыми ревизиями и байтами.

Данный прогон проверяет передачу, остановку, исправление пакета и приёмку фактических файлов.

Он не является первичной генерацией всей воронки, проверкой всех шести команд на реальном проекте, тремя читательскими кругами, браузерной сборкой или измерением продаж.

Малый тест намеренно использовал координатора для проверки протокола; в обычной работе такую правку можно отдать напрямую.

Экономия токенов, времени и подписочных лимитов сравнительным испытанием не установлена.

Протоколы, пакеты, исходные хеши и запись контролируемой подмены сохранены локально в игнорируемом runs/team-trial; личные данные и рабочие журналы в библиотеку не включены.
