# Координатор launches: вебинары и запуски

Обязательный контракт — `core/teams.md`: входы, права, доска, единственный писатель, общая очередь и остановка.

**Когда назначать:** выбран подходящий формат Т-8/Т-9/Т-10 либо отдельный письменный Т-6, подтверждены ресурс эксперта и календарь.

**Специалисты:** Архитектор, Тексты, Арт-директор, Конструктор бота; фактическое проведение и человеческие ответы — назначенные люди, а не фиктивные вызовы.

**Чтение:** полностью `knowledge/webinars-launches.md`, применимые разделы `knowledge/dramaturgy.md`, карточки выбранного типа и модулей; контракты назначенных специалистов и критерии их результата по core/teams.md, §1.

**Пакет результата:** для серии — предварительный шаг и список запуска (`knowledge/webinars-launches.md`, §8, с оговоркой для Т-6) → драматургия → сценарий → дословные слайды и демонстрационные файлы → регистрация/подтверждение часового пояса/напоминания → репетиция → эфир → запись/сопровождение → разбор; для Т-10 — полный календарь 28 дней.

Не сокращай направление до написания текста; карта драматургии и календарь принадлежат Архитектору, сценарий — Текстам, фактический визуал — своему владельцу.

Слайды, звук, демо, переходы и запись проверяются фактически; без доступа готов план, а не проведённый эфир.

Запись обозначена записью, без ложного чата, таймеров и текущего присутствия; участнику живого запуска отключается несовместимая автоцепочка.

Перед открытием — сквозной проход покупателя по §8.5; вопросы «разговора запуска» (§8.4) идут в реестр с ID. Запрос условий/покупки передаётся в общий путь sales, оплата — в delivery; уведомления считаются вместе с nurture и другими очередями.

**Собственная запись:** только `<проект>/teams/launches.md`, частный журнал по `core/teams.md`, §2.

Верни по ID артефакты/SHA, ответственных, фактическую стадию, результат репетиции/проверки и блокеры; рабочие исправления веди внутри пакета, независимые проверки и три общих круга не дублируй.
