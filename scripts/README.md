# Локальные инструменты

Python 3.9+, стандартная библиотека и Git для проверки зависимостей.

Команды выполняются из корня ГККД.

## Закреплённые зависимости

```sh
python3 scripts/check_dependencies.py --repos-root /path/to/sibling-repositories
python3 scripts/check_dependencies.py --repos-root /path/to/sibling-repositories --route audience
python3 scripts/check_dependencies.py --repos-root /path/to/sibling-repositories --route hvco
python3 scripts/check_dependencies.py --repos-root /path/to/sibling-repositories --route clip
python3 scripts/check_dependencies.py --repos-root /path/to/sibling-repositories --route copywriting
```

`--repos-root` обязателен и указывает на каталог соседних репозиториев с именами из [манифеста](../dependencies.json).

Без `--route` проверяются все зависимости; `audience` проверяет исследование, `hvco` и `clip` — свой компонент и copywriting, `copywriting` — только методички письма и восприятия на слух.

Недоступный компонент другого маршрута не блокирует выбранный маршрут, но схема манифеста всегда проверяется целиком.

Отсутствующий или неполный выбранный маршрут отклоняется как неверный манифест: `hvco` и `clip` обязательно включают собственный компонент и `promt-copywriting`.

Без `--route` манифест должен покрывать все четыре маршрута.

HEAD должен точно совпадать с полным закреплённым SHA: другой коммит отклоняется даже при одинаковых используемых файлах.

Каждый обязательный файл сравнивается байт в байт с `git show SHA:path`, включая изменения, скрытые флагами `assume-unchanged` или `skip-worktree`.

Сами флаги без изменения байтов не означают ошибку.

Грязный checkout, незакоммиченные посторонние файлы, отсутствующие файлы, символьные ссылки в пути checkout/обязательных файлов и небезопасные пути манифеста отклоняются.

Все обязательные файлы закреплённого checkout проверяются за один запуск, а не только первый найденный файл.

Команда не выполняет fetch, checkout, reset, запись файлов или отправку данных; Git вызывается с `--no-optional-locks` и `--no-replace-objects`, поэтому локальные `git replace` не подменяют закреплённые объекты.

Код возврата: `0` — всё совпало, `1` — зависимость не прошла проверку, `2` — неверный CLI или манифест.

Это проверка локальных снимков, а не семантическая проверка методологии и не защита от одновременного изменения файлов другим процессом.

## Полные разделы контекста

```sh
python3 scripts/context.py --file knowledge/methodology.md --heading '0. Рамка'
python3 scripts/context.py --file core/handoff.md --heading '1. Папка проекта эксперта' --heading '4. Контракты агентов'
python3 scripts/context.py --file path/to/card.md --heading 'Точный заголовок' --output /path/to/new-context.md
```

Для другого раздела скопируйте полное имя нужного заголовка из текущей редакции карточки.

`--file` и хотя бы один `--heading` обязательны; селектор — точный текст ATX-заголовка без начальных `#` и завершающих декоративных `#`.

Раздел включает свой заголовок, весь текст и все подразделы до следующего заголовка того же или более высокого уровня.

Ограничения длины и пересказа нет: методическая карточка возвращается полностью.

Несколько селекторов выводятся в порядке исходника; перекрывающиеся разделы объединяются без повторения текста.

Заголовки внутри fenced code blocks не считаются разделами; Setext-заголовки не поддерживаются.

Повтор селектора, неоднозначный или отсутствующий заголовок, скрытый Unicode format character, включая BOM, и неверный UTF-8 приводят к ошибке до вывода содержимого или создания результата.

Без `--output` текст идёт в stdout, с `--output` создаётся новый локальный UTF-8 файл; существующий файл никогда не перезаписывается.

Размеры и SHA-256 исходного текста и выделенного результата идут отдельно в stderr, чтобы сравнивать версии при повторном использовании.

Утилита не отправляет содержимое модели автоматически и не доказывает, что исполнитель прочитал карточку.

Код возврата: `0` — готово, `2` — ошибка.

## Проверки инструментов и структуры

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check_structure.py
```

Регрессионные проверки инструментов создают временные Git-репозитории и не меняют соседние рабочие проекты.

Структурная проверка охватывает корневые Markdown-файлы и каталоги `agents`, `core`, `knowledge`, `library`, `integrations`, `docs`, `scripts`: поддерживаемые локальные ссылки, метаданные агентов и скрытые Unicode format characters.

Она не заменяет отдельное ревью, полный синтетический прогон передачи и проверку реальной поверхности.
